PID 펌웨어 수정 계획
작성일: 2026-08-26

1. 목적

- 현재 main 펌웨어와 기존 PLC 프로그램을 사용하는 조건에서 20℃ -> 40℃ 가열 시 마지막 1℃ 구간의 과도한 지연을 줄인다.
- 40℃ -> 20℃ 냉각 제어에는 변경을 적용하지 않아 현재 냉각 진동이 더 커지는 것을 방지한다.
- PLC 프로그램, PLC 설정 화면 및 기존 칠러 운전 절차는 변경하지 않는다.

2. 현재 확인된 현상

- 분석 대상: 배관닫음/2자유도펌웨어 CSV 로그 16개.
- 최종 시험 조건의 가열 로그에서 다음 결과가 확인됨.
  - 가열 시작 -> 39℃: 약 96.7초.
  - 39℃ -> 39.9℃: 약 609.3초.
  - 39℃ -> 40℃: 약 857.2초.
- 최종 시험 조건의 냉각 정상상태 PV 진동폭은 약 0.558℃ P-P임.
- 전체 Kp를 증가시키면 가열은 빨라질 수 있지만 냉각 진동이 증가할 가능성이 있으므로 전체 구간의 Kp 증가는 적용하지 않는다.
- 최종 시험의 가열 NEAR 설정은 PB=12000, Ti=2400, Td=100이며 Ti 단위가 0.1초이므로 적분 시정수는 240초이다.

3. 수정 기본 방침

- PLC가 전달하는 configured PB/Ti/Td 값은 변경하지 않는다.
- 펌웨어 PID 계산에 사용하는 effective Ti만 조건부로 변경한다.
- 1차 수정에서는 Kp, Kd, 출력 제한, 냉각 로직 및 SP 필터를 변경하지 않는다.
- 가열 방향이면서 NEAR 구간일 때만 effective Ti를 1200(120초)으로 적용한다.
- 냉각 방향에서는 configured Ti를 그대로 사용한다.
- 한 번에 여러 제어 요소를 변경하지 않고 1차 시험 결과를 확인한 뒤 후속 변경 여부를 결정한다.

4. 펌웨어 내부 상태 추가 계획

4.1 운전 방향 상태

- SV 변경을 감지한 시점에 방향을 결정하여 저장한다.
  - 새로운 SV > 이전 SV: HEATING.
  - 새로운 SV < 이전 SV: COOLING.
  - 새로운 SV = 이전 SV: 기존 방향 유지.
- PV가 SV를 통과하더라도 저장된 방향을 변경하지 않는다.
- Enable 진입 시 현재 SV와 PV를 기준으로 방향 상태를 초기화한다.

4.2 FAR/NEAR 상태

- 절대 오차 |SV-PV|를 사용한다.
- FAR 상태에서 |SV-PV| <= 1.0℃이면 NEAR로 전환한다.
- NEAR 상태에서 |SV-PV| >= 1.3℃이면 FAR로 복귀한다.
- |SV-PV|가 1.0℃ 초과 1.3℃ 미만이면 기존 상태를 유지한다.
- 0.3℃ 히스테리시스를 사용하여 센서 노이즈로 인한 FAR/NEAR 반복 전환을 방지한다.
- Enable 진입 및 SV 변경 시 FAR로 초기화한다.

5. 1차 effective Ti 적용 조건

- 기본값:
  - effective Ti = configured Ti.
- 예외 조건:
  - direction == HEATING.
  - region == NEAR.
  - 위 두 조건이 모두 참이면 effective Ti = 1200으로 적용한다.
- 냉각 방향에서는 FAR/NEAR와 관계없이 effective Ti = configured Ti를 유지한다.
- 1차 수정에서는 PB와 Td를 변경하지 않는다.

개념 로직:

    effective_ti = configured_ti;

    if (direction == HEATING && region == NEAR)
    {
        effective_ti = 1200;
    }

6. 계수 전환 시 주의사항

- FAR -> NEAR 전환 시 PID 적분값을 0으로 초기화하지 않는다.
- Ti 변경 전후에 현재 적분 출력이 급변하지 않도록 기존 적분 상태를 유지한다.
- effective Ti 변경 시 Kp/Ti, Kaw 등 Ti에 종속되는 내부 계수를 같은 제어 주기에서 다시 계산한다.
- 설정값 필터에 Ti 종속 파생계수가 사용된다면 해당 파생계수도 함께 갱신한다.
- 계수 전환 직후 MV가 불연속적으로 튀지 않는지 CSV에서 확인한다.
- 출력 포화 시 기존 back-calculation anti-windup 동작을 유지한다.

7. 진단 로그 추가 계획

- 기존 CSV 열과 호환성을 우선한다.
- 가능하면 다음 값을 기록한다.
  - configured_pb/ti/td: PLC가 요청한 값.
  - effective_pb/ti/td: PID 계산에 실제 사용한 값.
  - control_direction_u16: 0=HEATING, 1=COOLING.
  - pid_region_u16: 0=FAR, 1=NEAR.
  - pid_params_pending 또는 configured/effective 불일치 표시.
- 로그를 통해 가열 NEAR에서만 effective Ti=1200이 적용됐는지 확인한다.
- 냉각 전 구간에서는 configured Ti와 effective Ti가 동일한지 확인한다.

8. 수정하지 않는 항목

- PLC 프로그램 및 PLC 운전 화면.
- PLC가 전송하는 PB/Ti/Td 및 alpha 설정 방식.
- 가열 및 냉각 배관·밸브 운전 순서.
- Kp에 해당하는 PB 값.
- Kd에 해당하는 Td 값.
- 가열 SP 필터 및 alpha 처리.
- 냉각 출력 증가율 제한.
- 출력 데드밴드 및 최소 출력.
- SMPS 출력 변환식.
- 기존 출력 상한·하한.

9. 구현 후 정적 확인 계획

1) main 브랜치와 수정 파일 목록을 기록한다.
2) 방향 상태가 SV 변경 시에만 결정되는지 확인한다.
3) PV가 SV를 통과할 때 방향 상태가 반전되지 않는지 확인한다.
4) FAR/NEAR 전환 조건이 1.0℃/1.3℃인지 확인한다.
5) effective Ti=1200이 HEATING+NEAR에서만 적용되는지 확인한다.
6) 냉각 계산 경로가 기존 코드와 동일한지 확인한다.
7) Ti 종속 내부 계수가 모두 갱신되는지 확인한다.
8) 빌드 경고와 오류를 기록한다.
9) HEX와 EXEC는 사용자 확인 후에만 갱신한다.

10. 칠러 재시험 계획

- 기존 시험과 동일한 장비 설정 및 운전 절차를 사용한다.
- 20℃ -> 40℃ 가열 후 40℃ -> 20℃ 냉각 시험을 수행한다.
- 기존과 동일한 CSV 주기로 기록한다.
- 다음 항목을 기존 최종 로그와 비교한다.
  - 가열 시작 -> 39℃ 도달시간.
  - 39℃ -> 39.9℃ 소요시간.
  - 39℃ -> 40℃ 소요시간.
  - 가열 오버슈트.
  - 목표값 ±0.1℃ 정착시간.
  - 냉각 90% 도달시간.
  - 냉각 언더슈트.
  - 냉각 정상상태 PV P-P 및 표준편차.
  - MV 최소/최대 및 FAR/NEAR 전환 시 MV 급변 여부.
  - fault 및 usb_dropped_count.

11. 1차 판정 기준

- 가열 39℃ -> 39.9℃ 시간이 기존 약 609초보다 유의하게 감소해야 한다.
- 가열 39℃ -> 40℃ 시간이 기존 약 857초보다 유의하게 감소해야 한다.
- 가열 오버슈트와 정상상태 진동이 허용 범위를 벗어나지 않아야 한다.
- 냉각 정상상태 진동폭이 기존 약 0.558℃ P-P보다 뚜렷하게 증가하지 않아야 한다.
- 냉각 configured/effective PID 값과 제어 경로가 기존과 동일해야 한다.
- fault와 USB drop이 발생하지 않아야 한다.

12. 1차 결과에 따른 후속 계획

- 가열 시간이 충분히 개선되고 진동이 허용 범위이면 1차 설정을 유지한다.
- 가열 개선이 부족하고 오버슈트가 작으면 가열 NEAR effective Ti를 1200에서 800으로 줄이는 2차 시험을 검토한다.
- 가열 진동 또는 오버슈트가 증가하면 effective Ti를 1200에서 더 큰 값으로 되돌리거나 1차 변경을 철회한다.
- 냉각 결과가 악화되면 방향 판정 및 계수 적용 경로를 우선 점검하고 기존 펌웨어로 복귀한다.
- SP 필터 우회, 방향별 Kp, 냉각 출력 변화율 제한은 1차 결과로 필요성이 확인되기 전까지 적용하지 않는다.

13. 복구 계획

- 수정 전 main 커밋과 기존 HEX/EXEC의 해시 및 생성 시각을 기록한다.
- 변경 사항은 별도 커밋 또는 패치로 관리한다.
- 이상 발생 시 해당 변경을 제거하고 기존 main 소스와 기존 실행 파일로 복귀한다.
